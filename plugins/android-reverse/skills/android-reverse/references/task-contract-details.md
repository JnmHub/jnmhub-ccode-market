# 用户需求与交付边界

把用户目标、明确约束和所需产物记在 report 的适当位置，不另建 task.json 或推导一套等级门禁。

- 尊重用户禁止项和已否决方案；关键歧义才澄清，不自动扩张任务。
- 区分识别某方案、实现该方案、在给定样例验证和对新输入验证。证据范围不能相互替代。
- 用户要求独立实现时，应说明真实依赖及限制，不能把调用原始组件或重放已有值说成独立实现。
- 验证方法由任务需要决定，记录真实命令、输入、输出与错误；不能为了形式检查制造样例。
- 用户需要的真实代码、日志、样本及构建产物保留。未完成或受阻时照实总结，不禁止回复。

report 写作见 ../docs/reference/output-contract.md。
