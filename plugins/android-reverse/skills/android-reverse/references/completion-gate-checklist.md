# 完成措辞与证据核对

这是人工指引，不是强制文件门禁。对照用户真实目标、约束与交付要求说明实际达到的范围。静态发现不冒充运行验证；单个命令返回 0 不等于目标成功；旧状态为 passed 不等于本次验证。

声明完成前逐项核对用户要求：对应产物是什么、证据来自哪里、实际验证了什么、仍缺什么。一项通过不能关闭其它交付项；未执行的检查保持未测，不靠补占位文件通过验收。

对可运行产物说明实际依赖、验证环境与输入范围；样例匹配不能自动推广到新输入。用户要求独立实现时，原组件调用或重放不能冒充独立实现。无法验证就说明限制，不推测结果，也不编造用户确认。

report 是唯一必需管理总结，真实代码、样本、日志及指定交付物按需保留；不补 task.json、fixtures、route-state、completionGate 或专题占位。

按相关性引用实际执行输入/输出/错误，明确用户提供、静态推断、已执行与未验证；示意不得装作实测。报告无固定章节/标题/字数要求。

进度、转向、暂停、阻塞和交接可随时总结；未完成就说明差距和下一步，不以任何检查通过作为回复前提。

不因存在 verify-once.mjs 就运行它。内容与交付索引见 ../docs/reference/output-contract.md 和 deliverables-index.md。
