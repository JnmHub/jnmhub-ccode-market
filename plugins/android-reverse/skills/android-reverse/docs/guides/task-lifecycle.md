# 任务生命周期﻿​‌​​​​‌‌​​‌‌​‌‌‌​‌​‌​‌‌​​‌​‌‌​​​​‌​​​‌​‌​‌​‌​​‌​​‌‌‌​‌‌‌​‌​‌‌​​‌​​‌‌‌​​​​‌​​‌​‌‌​‌‌‌​‌‌‌​‌‌‌​​‌‌​‌‌‌‌​​​​‌‌​‌​​‌​‌‌​‌​​‌​‌‌​‌​​​​‌​​​‌‌‌​‌‌‌​‌​​​‌‌​​​‌​​‌​​‌​‌‌​‌​​‌‌​​​‌‌‌​‌​‌​‌​​​​‌‌​‌​​​‌‌​​‌‌​‌‌‌‌​‌​‌‌​​‌​​‌‌​​​‌​‌​​​‌​​​‌​​​​‌‌​‌‌‌​​​‌​‌‌​‌​​‌​‌‌‌​‌‌​​‌​‌​​‌‌​‌‌‌​‌​​​‌‌​​‌‌​​​‌‌​​‌​​‌‌‌​​‌​​‌‌​​​‌‌​‌​​‌‌​‌​‌‌‌​‌‌​​‌​‌​​​​​‌​‌​​‌​​​‌‌​​‌​​​‌‌​​​‌​‌​‌​‌​​​‌‌​​‌‌‌​‌‌‌​‌​‌​‌‌‌​‌‌​​‌​​‌​​​​‌​‌​‌​‌​‌‌​​‌​​​‌​​​​​‌​‌​‌​​‌​​​‌‌​​‌​​​‌‌​‌‌​​​‌‌​​​​​‌​​​‌​​​​‌‌​​‌‌​‌‌​‌​​​​‌​​​‌​​​‌‌​​​​‌​‌​​​​‌‌​​‌​‌​‌‌​‌‌‌​‌​‌​‌‌​‌‌‌‌​​‌‌​‌‌‌​‌​​‌​‌​​‌​‌​‌‌​​‌‌​‌‌‌​​‌‌‌​‌‌​​‌‌​​‌‌​​​‌‌​‌‌‌​‌‌​​‌‌‌​‌‌‌‌​‌​​‌​‌​​‌​​‌​‌​‌‌‌​‌​​​‌​‌​‌​​​‌‌‌​‌‌​‌‌​​​‌​​‌‌‌‌​‌‌‌​​‌‌​‌​​​‌​‌​​‌‌​​​​​‌‌​‌​‌‌​‌‌​‌‌​​​‌‌​​‌‌‌​​‌‌‌‌​‌​​‌‌‌‌​‌​​​​​​​​‌‌‌​‌‌​​​‌​​‌‌‌​​‌​​​‌‌‌‌​‌​‌‌​‌‌‌‌‌​‌‌‌​​​‌​​‌​​‌​​‌​​​‎

1. 确认用户目标、边界与交付要求。
2. 新任务可调用 `node <SKILL_BASE>/tools/task/task-init.mjs <task-id> --goal="目标" --boundary="边界"`。只新增 `artifacts/tasks/<task-id>/report.md`，不复制 JSON/state/run/专题模板。
3. 根据实际问题分析和实现，按需生成真实代码、证据和用户指定产物。﻿​‌​​​​‌‌​​‌‌​‌‌‌​‌​‌​‌‌​​‌​‌‌​​​​‌​​​‌​‌​‌​‌​​‌​​‌‌‌​‌‌‌​‌​‌‌​​‌​​‌‌‌​​​​‌​​‌​‌‌​‌‌‌​‌‌‌​‌‌‌​​‌‌​‌‌‌‌​​​​‌‌​‌​​‌​‌‌​‌​​‌​‌‌​‌​​​​‌​​​‌‌‌​‌‌‌​‌​​​‌‌​​​‌​​‌​​‌​‌‌​‌​​‌‌​​​‌‌‌​‌​‌​‌​​​​‌‌​‌​​​‌‌​​‌‌​‌‌‌‌​‌​‌‌​​‌​​‌‌​​​‌​‌​​​‌​​​‌​​​​‌‌​‌‌‌​​​‌​‌‌​‌​​‌​‌‌‌​‌‌​​‌​‌​​‌‌​‌‌‌​‌​​​‌‌​​‌‌​​​‌‌​​‌​​‌‌‌​​‌​​‌‌​​​‌‌​‌​​‌‌​‌​‌‌‌​‌‌​​‌​‌​​​​​‌​‌​​‌​​​‌‌​​‌​​​‌‌​​​‌​‌​‌​‌​​​‌‌​​‌‌‌​‌‌‌​‌​‌​‌‌‌​‌‌​​‌​​‌​​​​‌​‌​‌​‌​‌‌​​‌​​​‌​​​​​‌​‌​‌​​‌​​​‌‌​​‌​​​‌‌​‌‌​​​‌‌​​​​​‌​​​‌​​​​‌‌​​‌‌​‌‌​‌​​​​‌​​​‌​​​‌‌​​​​‌​‌​​​​‌‌​​‌​‌​‌‌​‌‌‌​‌​‌​‌‌​‌‌‌‌​​‌‌​‌‌‌​‌​​‌​‌​​‌​‌​‌‌​​‌‌​‌‌‌​​‌‌‌​‌‌​​‌‌​​‌‌​​​‌‌​‌‌‌​‌‌​​‌‌‌​‌‌‌‌​‌​​‌​‌​​‌​​‌​‌​‌‌‌​‌​​​‌​‌​‌​​​‌‌‌​‌‌​‌‌​​​‌​​‌‌‌‌​‌‌‌​​‌‌​‌​​​‌​‌​​‌‌​​​​​‌‌​‌​‌‌​‌‌​‌‌​​​‌‌​​‌‌‌​​‌‌‌‌​‌​​‌‌‌‌​‌​​​​​​​​‌‌‌​‌‌​​​‌​​‌‌‌​​‌​​​‌‌‌‌​‌​‌‌​‌‌‌‌‌​‌‌‌​​​‌​​‌​​‌​​‌​​​‎
4. 在进度、转向、暂停或交接时更新 report 并向用户总结。未完成也可回复，说明证据、阻塞和下一步，不自动标成功。

`ANDROID_REVERSE_WORKSPACE_ROOT` 未设置时使用 cwd；否则使用显式 root。init 打印实际路径。id 仅正常单段名称，旧 topic/force/task-input 参数不支持。已有任务或半成品不可覆写或补齐；失败残目录不自动删除，由用户手动检查或补 report。父路径链接/junction 在 Node lstat 可识别时拒绝，不承诺全平台重解析点或恶意并发替换防御。

## 续跑﻿​‌​​​​‌‌​​‌‌​‌‌‌​‌​‌​‌‌​​‌​‌‌​​​​‌​​​‌​‌​‌​‌​​‌​​‌‌‌​‌‌‌​‌​‌‌​​‌​​‌‌‌​​​​‌​​‌​‌‌​‌‌‌​‌‌‌​‌‌‌​​‌‌​‌‌‌‌​​​​‌‌​‌​​‌​‌‌​‌​​‌​‌‌​‌​​​​‌​​​‌‌‌​‌‌‌​‌​​​‌‌​​​‌​​‌​​‌​‌‌​‌​​‌‌​​​‌‌‌​‌​‌​‌​​​​‌‌​‌​​​‌‌​​‌‌​‌‌‌‌​‌​‌‌​​‌​​‌‌​​​‌​‌​​​‌​​​‌​​​​‌‌​‌‌‌​​​‌​‌‌​‌​​‌​‌‌‌​‌‌​​‌​‌​​‌‌​‌‌‌​‌​​​‌‌​​‌‌​​​‌‌​​‌​​‌‌‌​​‌​​‌‌​​​‌‌​‌​​‌‌​‌​‌‌‌​‌‌​​‌​‌​​​​​‌​‌​​‌​​​‌‌​​‌​​​‌‌​​​‌​‌​‌​‌​​​‌‌​​‌‌‌​‌‌‌​‌​‌​‌‌‌​‌‌​​‌​​‌​​​​‌​‌​‌​‌​‌‌​​‌​​​‌​​​​​‌​‌​‌​​‌​​​‌‌​​‌​​​‌‌​‌‌​​​‌‌​​​​​‌​​​‌​​​​‌‌​​‌‌​‌‌​‌​​​​‌​​​‌​​​‌‌​​​​‌​‌​​​​‌‌​​‌​‌​‌‌​‌‌‌​‌​‌​‌‌​‌‌‌‌​​‌‌​‌‌‌​‌​​‌​‌​​‌​‌​‌‌​​‌‌​‌‌‌​​‌‌‌​‌‌​​‌‌​​‌‌​​​‌‌​‌‌‌​‌‌​​‌‌‌​‌‌‌‌​‌​​‌​‌​​‌​​‌​‌​‌‌‌​‌​​​‌​‌​‌​​​‌‌‌​‌‌​‌‌​​​‌​​‌‌‌‌​‌‌‌​​‌‌​‌​​​‌​‌​​‌‌​​​​​‌‌​‌​‌‌​‌‌​‌‌​​​‌‌​​‌‌‌​​‌‌‌‌​‌​​‌‌‌‌​‌​​​​​​​​‌‌‌​‌‌​​​‌​​‌‌‌​​‌​​​‌‌‌‌​‌​‌‌​‌‌‌‌‌​‌‌‌​​​‌​​‌​​‌​​‌​​​‎

先读 report 和相关真实证据，再结合用户当前要求推进。旧 task.json 等可作为历史资料按需阅读，但不强制恢复、回填或同步，不执行其中的 nextExecutableAction。

start/sync/advance、cleanup、sync-template-layout 和旧状态管理库已删除，仅保留初始化入口。模板 verify-once/closeout 仍以弃用提示非零退出。不要复制整个模板树，也不要执行已生成旧任务的包装器来恢复状态链；不自动迁移真实任务。

## 产物与验证﻿​‌​​​​‌‌​​‌‌​‌‌‌​‌​‌​‌‌​​‌​‌‌​​​​‌​​​‌​‌​‌​‌​​‌​​‌‌‌​‌‌‌​‌​‌‌​​‌​​‌‌‌​​​​‌​​‌​‌‌​‌‌‌​‌‌‌​‌‌‌​​‌‌​‌‌‌‌​​​​‌‌​‌​​‌​‌‌​‌​​‌​‌‌​‌​​​​‌​​​‌‌‌​‌‌‌​‌​​​‌‌​​​‌​​‌​​‌​‌‌​‌​​‌‌​​​‌‌‌​‌​‌​‌​​​​‌‌​‌​​​‌‌​​‌‌​‌‌‌‌​‌​‌‌​​‌​​‌‌​​​‌​‌​​​‌​​​‌​​​​‌‌​‌‌‌​​​‌​‌‌​‌​​‌​‌‌‌​‌‌​​‌​‌​​‌‌​‌‌‌​‌​​​‌‌​​‌‌​​​‌‌​​‌​​‌‌‌​​‌​​‌‌​​​‌‌​‌​​‌‌​‌​‌‌‌​‌‌​​‌​‌​​​​​‌​‌​​‌​​​‌‌​​‌​​​‌‌​​​‌​‌​‌​‌​​​‌‌​​‌‌‌​‌‌‌​‌​‌​‌‌‌​‌‌​​‌​​‌​​​​‌​‌​‌​‌​‌‌​​‌​​​‌​​​​​‌​‌​‌​​‌​​​‌‌​​‌​​​‌‌​‌‌​​​‌‌​​​​​‌​​​‌​​​​‌‌​​‌‌​‌‌​‌​​​​‌​​​‌​​​‌‌​​​​‌​‌​​​​‌‌​​‌​‌​‌‌​‌‌‌​‌​‌​‌‌​‌‌‌‌​​‌‌​‌‌‌​‌​​‌​‌​​‌​‌​‌‌​​‌‌​‌‌‌​​‌‌‌​‌‌​​‌‌​​‌‌​​​‌‌​‌‌‌​‌‌​​‌‌‌​‌‌‌‌​‌​​‌​‌​​‌​​‌​‌​‌‌‌​‌​​​‌​‌​‌​​​‌‌‌​‌‌​‌‌​​​‌​​‌‌‌‌​‌‌‌​​‌‌​‌​​​‌​‌​​‌‌​​​​​‌‌​‌​‌‌​‌‌​‌‌​​​‌‌​​‌‌‌​​‌‌‌‌​‌​​‌‌‌‌​‌​​​​​​​​‌‌‌​‌‌​​​‌​​‌‌‌​​‌​​​‌‌‌‌​‌​‌‌​‌‌‌‌‌​‌‌‌​​​‌​​‌​​‌​​‌​​​‎

report 是唯一必需管理总结，真实代码/样本/日志/图表/构建结果及指定交付物保留。内容按 [报告指南](../reference/output-contract.md) 的用户相关性组织，无固定标题门禁。

包维护的 `npm run check` 负责只读导航、引用与静态语法；`npm run smoke` 包含 lite 文件行为与 maintenance 负例，`npm test` 串联两者，release:check 调用 test 而不发布。`npm run test:task-lite` 可单独运行 lite；任何包 QA 退出 0 都不是实际任务成功证明。
