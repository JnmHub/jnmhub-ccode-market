# 报告与交付指引

report.md 是唯一必需的管理总结文档，不是唯一允许存在的文件。真实代码、样本、日志、图表、构建产物和用户明确要求的交付物按需生成并保留，不因形式检查或清理规则丢弃。

## 面向用户的内容（人工写作指引）

按相关性说明以下信息，可以合并、改变标题、调整顺序或无标题；无关项直接省略，不要求 N/A：

- 概览：用户目标、约束、已知背景、实际结果范围。
- 思路与实现：为什么选这条路线，关键步骤，已实现与未实现部分。
- 难点与坑：实测错误、环境限制、容易误判处及依据。
- 防御与环境：用户提供或实际发现的检测/防护、设备与工具条件；区分来源，不补造未测试的子面。
- 溯源调用链：相关时说明入口到关键处理和输出的链路，标清静态推断与运行证据。
- 试错与转向：尝试了什么、实际结果、为何改变路线；不补录不存在的历史。
- 算法方案：相关的输入输出、方案边界、验证样例和限制，不把识别算法名说成完整实现。
- 资产与方法：脚本、样本、日志或其它真实产物的位置、用途和复用限制。
- 成果例子：实际执行的输入、输出及证据；示意例子明确标注“未执行/未验证”。
- 其它用户需要知道的风险、阻塞、未完成项及下一步。

这是覆盖信息的建议，不是固定标题、关键词、字数、章节顺序或机器评分条件。不另建完整性 JSON、walkthrough、summary 或覆盖清单。报告语言服从用户需要，不强制所有报告同一语言。

## 稳定交接信息

在关键变化、暂停或交接时，把会影响后续判断的信息保存在 report 中：用户目标与明确禁止项、关键证据位置及来源、已失败方法和实际原因、尚未验收的要求、下一待确认问题。标题和顺序自由；没有某类事实就说明未知或省略，不编造历史，也不要求额外台账。

明确否决记录原话或忠实摘要；用户的疑问不等于永久禁止。恢复时先读这些信息与用户最新要求；必要时只读历史文件查找遗漏约束，不执行历史命令，不把旧 passed 当本次证据。

## 逐项验收

使用“完成”措辞前，按 ../../references/completion-gate-checklist.md 逐项核对用户要求、实际产物、验证证据与限制；报告中用段落或表格表达核对结果即可，不建立固定格式门禁。核对口径以该文件为唯一权威，本文件不再重复列举。

## 随时总结，不自动成功

正常进度、路线转向、暂停、阻塞与交接都可随时向用户总结并更新 report；不以全任务完成作为回复前提。结论引用真实证据，区分用户提供、静态推断、已执行与未验证。未完成就说明差距，不能因单项通过或旧状态为 passed 自动声称成功。
