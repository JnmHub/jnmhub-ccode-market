# Pure Extraction

进入 `PureExtraction` 前，建议核对（参考项，非进入门禁，不因未满足而禁止推进）：

- 关键证据已捕获
- 本地重建或最小复现已稳定
- 能明确划分”平台噪音”和”纯算法 / 纯逻辑”边界

## 验证参考（不设固定进入门禁）

进入前建议按目标与证据风险选择验证方式；以下做法可作为参考，不构成数量门禁，也不因未满足而禁止推进：

1. **证据闭环**：切入点证据链（输入 → 处理 → 输出）完整；样本有限时如实说明可覆盖的输入范围
2. **复现稳定**：相同输入重复执行结果一致；固定重复次数不替代有区分能力的验证
3. **噪音可识别**：能区分平台相关项（如 Android API 调用、设备状态读取、进程间通信）与核心算法/逻辑

## “平台噪音” vs “纯算法/逻辑”判定

- **平台噪音**：依赖 Android API（Context / SharedPreferences / TelephonyManager）、设备状态（build fingerprint / screen size）、运行时环境（SELinux / process UID）的操作
- **纯算法/逻辑**：仅依赖输入参数和常量（密钥 / IV / 盐值 / 算法标识）即可独立计算的部分
- **灰色地带**：从设备属性派生的参数（如 ANDROID_ID 用于密钥派生）——记录派生方式，将派生参数视为算法输入而非平台依赖

## 进入后

- 只保留与业务结果直接相关的计算路径
- 最终实现与临时分析依赖分离；保留原始日志、样本与修改记录，不把交付精简解释为删除证据。确需删除资产时另行明确范围并取得用户确认
- 将平台相关参数替换为可配置输入（从配置文件 / 环境变量读取）
- 若可移植，再进入 `Port`
