# Reverse Workflow

按用户目标与证据推进，而不是按状态文件自动执行。可用“观察 → 提出假设 → 验证 → 评价 → 调整”组织工作；不规定路线数量、尝试次数或全阶段遍历。

- 观察已有输入，分清用户提供、静态推断、真实执行结果和未知。
- 选择与问题相关的最小验证，只有在授权且风险可接受时执行。
- 记录实际输入、输出、错误与限制，保留真实脚本和证据。
- 证据不足时说明依据，不凭旧 passed 状态复用结论。准备重复失败方法前，说明新增条件与预期信息增益；没有新增依据则停止重复并报告输入缺口，不机械穷尽路线。
- 在关键变化、暂停或交接时，用 report 保存目标与禁止项、关键证据位置、已失败方法及原因、未验收项和下一待确认问题；不强制 route-state、route-plan、clues、progress 或其它管理台账。

技术阶段名称可用于说明，不是默认执行指令或回复门禁。总结不要求任务已完成；不能把局部验证、模板齐全或命令返回 0 当整体成功。

## 交付

结合用户实际要求交付真实产物；report 是唯一必需管理总结，其内容见 output-contract.md，无固定标题。

不调用 task-sync/advance、verify-once/closeout 包装器或 task-cleanup。既有资产保留，未完成项诚实说明。
