# Fallbacks

- 缺少动态样本：先收敛静态证据、入口、导入面和下一跳需求
- 工具不可用：回到最低依赖链路，优先保留可验证证据
- 无法稳定附加：先判断权限、架构、PPL/EDR、反分析与替代注入路线
- 无法直接解包：先记录 OEP 候选、内存保护变化、解密/映射路径

## 重工具调用判级细则（MCP 重型调用：IDA/idalib/radare2/cheatengine）

判级程序（先分类事件，再执行动作；拿不准一律按「有毒」处理——降级代价秒级，盲目重试代价实测达 18.7min，成本不对称）：

| 触发条件 | 动作 | 降级目标 |
|---|---|---|
| 长静默后传输层断（调用远超常态耗时后断连/超时/MCP 进程被杀） | 判该调用有毒：禁止原参数重发；只允许一次缩范围探活（更小的函数/更短的区段） | 再败按降级阶梯换接口家族（见下） |
| 快速配置类报错（permission denied / 秒级连接失败） | 判通道不可用：不重试 | 换通道（idalib ↔ r2 MCP ↔ Bash r2 CLI），降级声明（原通道/降级通道/原因）收口时记入 `report.md` 的「坑点与经验」节 |
| 带业务错误信息的返回（函数不存在/参数非法/分析未完成等） | 读信息行事：修正参数或先补前置步骤 | 不适用前两条 |
| 通道能力边界报错（接口不支持该操作/超出通道能力范围） | 读信息行事：缩范围或换同族接口 | 同族接口内降级 |

降级阶梯（写死，逐级换接口家族，不在同级原参重发）：

1. `decompile_function`（大函数/全量反编译先缩范围：单函数、单地址）
2. `disassemble_function`
3. 裸 `disassemble` 分段（按页/按块推进）
4. `hexdump` / `read_memory` 取证（人工判读字节）
5. 兜底级：Bash 调 r2 CLI + OS 级超时——agent 唯一握有生死开关的形态

兜底级命令示例（前提：宿主机 r2 CLI 可用；`run/env-capability.json` 的 `fallbackLadder.r2Cli` 已探测标注）：

```bash
# Bash / Git Bash
timeout 60 r2 -qc 'pdc @ 0x140001000' target.exe
```

```powershell
# PowerShell 等效（无 GNU timeout 时）
$job = Start-Job { r2 -qc 'pdc @ 0x140001000' target.exe }
if (-not (Wait-Job $job -Timeout 60)) { Stop-Job $job; "TIMEOUT: killed after 60s" } else { Receive-Job $job }
Remove-Job $job -Force
```

配套纪律：

- 无状态接口优先（单次调用自包含，不依赖长会话状态）。
- `analyze` 全量 ≈3min/次且进程被杀后缓存全失：非必要不 re-analyze；分析产物随手落盘 `run/`。
- 长输出落盘后摘要读取，不整段刷屏。

经验耗时（超 2× 预期耗时即判长静默，对应判级第 1 条）：

| 调用 | 预期耗时 |
|---|---|
| `decompile_function` 单函数 | 秒级 ~ 2min |
| `analyze` 全量 | ≈3min |
| `idb_open` | 秒级 |

## 动态通道试错预算律（advisory 自律级）

> 定性声明：本律为 **advisory 自律级**行为规则，无会话内强制机制——诚实边界显式声明：执行靠自律，事后以收口 `report.md` 的「坑点与经验」节审计兜底可见性（report-only 改造：原 `run/assumptions.md` 台账载体退役），不伪装成机器兜底。

**触发 A（预算线）**：同一动态通道自最近一次取得**目标运行时数据**起，累计 **K=12** 次调用仍未取得目标数据 → 该通道降级为只读探活并回静态主线复盘一次假设。环境事实类 informative 返回**不重置**计数。

**触发 B（系统性受损线）**：同一通道**第 2 次**出现通道级环境事实（上下文重建 / API 整族缺失 / 会话失效类）→ 直接降级；与 A 不累加、先到先触发。

**K 取值依据（结构性双锚点，拒绝裸常数）**：锚点一=首个目标运行时数据出现在该通道第 19 次调用（此前 18 次未取得目标数据）；锚点二=其后第 20–34 次共 15 次零目标数据沉没段；K≈⌈18×2/3⌉。K 与「第 2 次」均为 acceptance-criteria 登记的可调参数，任何调整必须附新一轮实证的双锚点数值，禁止无锚点调参。

**对象划界句**：本律约束探索路径与工具预算，不改变任何验证义务：动态交付类的末级禁令仍然完全适用——预算触发的合法出口是『换动态通道 / 只读探活维持 / 上报环境缺陷待修 / 请用户介入』四选一，唯独不是宣布纯静态替代交付；任何情况下禁止把'通道预算耗尽'写成'目标无该行为'的实质结论。（与下文「CE 家族降级阶梯」末级保护条款同向互证。）

**方法层对齐**：方法级止损的分级预算（L1/L2/L3）见 `references/anti-shortcut-system.md`「路线预算分级」；L2 探针预算复用本律 K=12 与其双锚点，两处任一调参必须同批登记 `docs/reference/acceptance-criteria.md` §13。

**载体说明**：触发时的计数与降级声明（原通道/降级通道/原因 + 累计试错计数）收口时写入 `report.md` 的「坑点与经验」节；不新建台账文件、不给 task-sync 加探测逻辑。

## CE 家族降级阶梯（cheatengine MCP 通道失效）

判级三分法与上文通用（CE 调用同样按「长静默 / 配置错 / 业务错误」分类，拿不准一律按有毒处理）。CE 通道被判有毒或不可用后的动作序列（逐级推进，不在同级原参重发）：

1. **探活重连**：`ping` 一次；失败则 `open_process` 重连目标进程。MCP 进程重启的秒级瞬断按通用规则允许一次只读重发，以区分瞬断与权限拒绝。
2. **CE GUI 手动步骤交接用户**：bridge 死但 CE 本体活着时，把要在 GUI 里执行的操作（指针扫描、Find what accesses、断点设置）写成逐步清单交给用户执行，取回结果截图或文本后继续。
3. **PowerShell 只读内存模板**：`pwsh "<SKILL_BASE>/tools/verify/ps-read-memory.ps1" -TargetPid <pid> -Regions`（区域枚举）与 `-Address 0x... -Size N`（读内存）。OpenProcess/VirtualQueryEx/ReadProcessMemory 三件套只读不写；直接抄模板，禁止即兴重写 P/Invoke / Marshal / GCHandle 样板。
4. **末级：声明降级为纯静态分析**，降级登记（原通道/降级通道/原因，含失败尝试）收口时记入 `report.md` 的「坑点与经验」节。注意：交付物本身是动态内存操作的任务（游戏坐标定位、实时状态读取等），纯静态降级等于放弃交付——此类任务应在阶梯 2/3 内解决，而不是跳末级；任何情况下禁止把"通道不可达"写成"目标无该行为"的实质结论。

## 交互式与后台进程处置

- stdin 交互式靶标一律管道/输入文件喂入 + OS 级超时包裹，禁止裸后台起交互进程。
- 后台 blocking 轮询预算 ≤2 次（单次 ≤120s）；超预算即 TaskStop/taskkill 并改同步前置喂入重试。
- taskkill 清理残留属许可家务动作，无需降级声明。

案例（一行）：B 会话对 idalib `decompile_function` 挂死零推理本能重试同参调用，78.7min 死区中 18.7min 纯由重试造成——同参重发次数必须为 0。
