# Miniapp（小程序）逆向总纲 Playbook

> 本文件是 `miniapp` 专题的主协议（topic protocol）。覆盖微信小程序为主战场、支付宝/抖音/百度/QQ 等为延伸的**全平台小程序逆向**。
> 微信平台深挖（V1MMWX 标定、运行时通道、签名模式库、验收编排）见 `wechat-miniprogram-playbook.md`；本文件负责：对象模型、平台矩阵、主链与分流判据、通道全景、交付映射、专题接线。
> 证据基线：16 个真实微信小程序逆向任务的全流程产物（见本文各章「实测」标注）+ 2024–2026 社区调研（时效标签随文标注）。

---

## 0. 专题坐标与边界

- **本专题是什么**：小程序 = 「受控 JS 运行时 + 平台包格式 + 平台 API 面」的复合逆向对象。任务是拿到包、还原逻辑层代码、复现其网络协议/签名，交付可独立运行的客户端或可控复用通道。
- **主辅关系**：目标识别为小程序 → `primary=miniapp`；签名/混淆/补环境等**技术专题**（signature、userland-crypto、jsvmp、env…）作为 secondary 按证据接入，不要为了"更完整"提前铺开。
- **边界**：微信/支付宝客户端本体、APK、native 层（mmtls 协议本体、WMPF 进程内部）归 android-reverse / win-reverse；本专题到「小程序 JS 与接口层」为止。普通小程序**开发**不适用本 skill。
- **合规**：小程序包与接口属目标方资产；本专题面向授权分析/安全评估/互操作场景。强制开调试、注入类工具有账号风控与 ToS 风险，仅授权环境使用。

## 1. 对象模型：先建立正确的心智

小程序与网页的本质差异决定了所有手法差异：

1. **双线程架构**：逻辑层（AppService，纯 JS 无 DOM/BOM）+ 渲染层（WebView）分线程运行，经平台桥通信。逆向主战场在 **AppService**——业务代码、签名、请求封装全在这里；在 WebView 里搜不到业务 JS 不是代码不存在，是线程错了。
2. **网络不走浏览器栈**：`wx.request` 等请求由客户端**原生网络进程**发出——这解释了两个实测现象：① DevTools/CDP 的 Network 域对小程序请求**时灵时不灵**（见 §4）；② PC 端系统代理（mitmproxy）反而能全量捕获。
3. **受控环境**：无 `window`/`document`、有 `wx.*`（或 `my.*`/`tt.*`/`swan.*`/`qq.*`）平台 API、强制合法域名校验（小程序管理后台配置）。本地复现时环境桩只需补 `wx.*` 用到的那几个函数，不是补浏览器。
4. **包即源码**：小程序包（wxapkg/TPKG/…）是编译产物的容器，解密+解包即可得到**可读 JS 工程**（常为 webpack/uni-app 压缩单行 bundle）。「取包→解包」成功 = 静态分析面全部打开，这是小程序逆向区别于 Web 逆向的最大红利。

## 3. 通用主链（16 个真实任务归纳出的统一骨架）

```
取包 → 解密解包 → 定性 → 定位 → 复现验收
```

1. **取包**：本机客户端缓存按 appid 检索是首选（无需真机/抓包）。微信路径矩阵见微信 playbook §1。**原样复制进任务目录并记 SHA-256**，一切解密在副本上进行。
2. **解密解包**：agent 环境首选 wx-mp `mp_analyze`（MCP 面直达）；通用环境首选 KillWxapkg（兼作逐字节校验基准）。非微信先试 unveilr / 平台专用解包器。产出标准工程目录（pages/components/app.js/app.json + `app-service.js`）。
3. **定性（最关键的 10 分钟）**：crypto 信号扫描只作初判——`ENCRYPTED` ≠ 有业务签名（实测多来自打包进去的 crypto-js/SDK 自用噪声），**无显式 sign 函数名也不等于无签名**（实测存在零 sign 命名但实有双层真签名的目标）。唯一可靠定性 = 沿请求封装调用链读到 header 构造点人工确认。定性直接决定是否投入签名破解路线。
4. **定位**：**不信自动报告的"API 列表"**（uni-app 产物里那是页面路由）——用 grep 找请求封装函数（`wx.request(` / `globalRequest(` / 签名 header 名如 `sign`/`OP-Authorization`），沿调用链读到 header 构造点。单行压缩 bundle 的阅读术见微信 playbook §3.2。
5. **复现验收**：纯 Python（标准库/requests）或 Node（内置 fetch）客户端 + `run/fixtures.json` 服务端真实响应留证 + 一键验收脚本。验收 = 服务端业务成功码 + 真实数据非空，不是"格式被接受"。

### 三个分流判据（决定路线形态，实测提炼）

- **判据 1 · 签名有无**：先定性再投入。无签名目标的真防线常是**请求头上下文**而非密码学（见下）。
- **判据 2 · 能力沉淀在哪**：业务数据在**自有 HTTP 后端**（→ 直连复现，主线）还是**平台原生插件/私有通道**（微信 `plugin-private://` + mmtls：CDP 与 MITM 均不可见 → 走「桥接触发 + 抓产物 + 缓存式脱机」降级交付，见微信 playbook §6.5）。
- **判据 3 · 鉴权门槛**：匿名可调 / 游客门控（补上下文头即通）/ 需登录 token。登录态边界见微信 playbook §7——`wx.login` 的 code 必须在真实微信环境产生，纯脚本无法自产，这是**协议级边界**，直接写进交付形态（用户供 token），不要硬顶。

### 无签名目标的真防线：请求头上下文（实测最高频）

PC 微信发出的每个小程序请求自动携带 `Referer: https://servicewechat.com/<appid>/<版本>/page-frame.html`，部分后端再叠加 `app-env`/`app-device`/`app-version`/`app-uuid` 等头族。**缺这些头 → 游客门控（如 `data.state="limit:tourist"`）或拦截；补齐即通行，无需任何签名**。指纹类头（版本号/uuid）实测多为弱校验。复现脚本里这组头是标配模板。

## 4. 通道全景与选择（按实测可靠性排序）

| 通道 | 干什么 | 实测可靠性 | 何时启用 |
|---|---|---|---|
| **静态解包产物** | 全文检索、精读算法、端点枚举 | ★★★★★ 主力 | 永远第一 |
| **服务端直接验收**（探针直发） | 把"还原对不对"变成服务端判定 | ★★★★★ | 有复现脚本后每轮必跑 |
| **mitmproxy 系统代理（PC）** | wx.request 全量抓包 | ★★★★☆ 实测唯一可靠的网络取证 | 静态存疑、门控差异比对、软风控观察 |
| **wx-mp 沙箱**（`mp_sandbox_run`） | 离线跑真实 bundle：钉死签名向量、调导出函数、三态验证 | ★★★★☆ | 签名函数可离线调用时（私钥/密钥能拿到） |
| **WMPF devtools 桥 + 裸 CDP** | 运行时实读 globalData、抓真实包、触发页面行为 | ★★★☆☆ 能用但有失效形态 | 静态+验收走不通、需要运行时真值时 |
| **miniapp-cdp MCP** | 上述能力的 MCP 封装 | ★★☆☆☆ 封装层三种失效形态 | 先探测，枚举不到 target 立即降裸 CDP |
| **微信开发者工具**（导入还原工程） | 可视化断点/调试 | ★★★☆☆【社区·本批会话零使用】 | 工程能被工具接受时 |

失效形态与降级链的完整细节（含裸 CDP 扁平会话序列）见微信 playbook §4；工具无关能力映射见 `browser-mcp-capability-map.md` 小程序通道节。

**通道纪律**（16 会话共性教训）：
- 动态通道**按需启用，不默认启用**——纯静态 + 服务端验收闭环的任务占比最高、速度最快。
- 通道失效先降级同端点的裸协议（MCP → 裸 CDP WS），再换通道；每换一个通道都要重验指纹/上下文。
- 抓包任务结束留**清理清单**：代理还原、CA 卸载、抓包进程停止。

## 5. 交付梯度在小程序语境的映射

- **A 请求验收**：补头/签名后服务端返回业务成功码（微信实测：不同后端成功码各异，以源码判定分支为准）。
- **B 内容边界**：目标是"读到内容/数据"而非复现协议时，匿名/游客可达即交付（实测：gkdg 零修改直读形态）。
- **C 浏览器内可控复用** → 小程序语境变体：**真实客户端内触发 + 桥接取证**（如合成事件调页面实例方法起播、wx.reLaunch 触发 onShow 发包）。
- **D 本地复现 / Port**（最常见交付）：`pure-*.py/js` 独立客户端。标准三件套：**可独立运行的 pure-* 脚本 + fixtures.json 真实响应基线 + 验收脚本/日志**。
- **降级形态 · 缓存式脱机**：当目标能力锁在平台原生通道（插件 mmtls / 服务端密钥签名的媒体直链）无法协议复现时，交付 = 桥接触发 prefetch + TTL 缓存产物 + 离线查询器。结论精度如实标注（provisional），不冒充全量复现。
- **E 纯算法提取**：签名函数扣出 + 最小 wx 环境桩跑通（接 `closure-extraction-playbook.md`，把 wx.* 当 env 面处理）。

## 7. 风险与合规提示

- 强开调试（WMPF patch/注入类工具）：对客户端的改写行为，有**账号风控 + 版本升级失效**双重风险，仅授权环境、自备小号。
- 证书安装、系统代理改动：任务结束按清理清单还原。
- 复现脚本**不得**携带真实用户 token/密钥硬编码进交付物；密钥一律运行时自举或用户供给。
- 各平台包格式与接口属目标方资产；工具链存在同名 fork 夹带私货的情况，解包工具认准上游并核对哈希。
