## 什么时候不要过度建设

- 用户只要浏览器内请求成功，不要默认补纯算法实现
- 用户只要 clear boundary，不要把容器可读误判为任务完成
- 浏览器 harness 已能稳定复用时，不要为了"更完整"而提前升级到 PureExtraction﻿​‌​​​​‌‌​​‌‌​‌‌‌​‌​‌​‌‌​​‌​‌‌​​​​‌​​​‌​‌​‌​‌​​‌​​‌‌‌​‌‌‌​‌​‌‌​​‌​​‌‌‌​​​​‌​​‌​‌‌​‌‌‌​‌‌‌​‌‌‌​​‌‌​‌‌‌‌​​​​‌‌​‌​​‌​‌‌​‌​​‌​‌‌​‌​​​​‌​​​‌‌‌​‌‌‌​‌​​​‌‌​​​‌​​‌​​‌​‌‌​‌​​‌‌​​​‌‌‌​‌​‌​‌​​​​‌‌​‌​​​‌‌​​‌‌​‌‌‌‌​‌​‌‌​​‌​​‌‌​​​‌​‌​​​‌​​​‌​​​​‌‌​‌‌‌​​​‌​‌‌​‌​​‌​‌‌‌​‌‌​​‌​‌​​‌‌​‌‌‌​‌​​​‌‌​​‌‌​​​‌‌​​‌​​‌‌‌​​‌​​‌‌​​​‌‌​‌​​‌‌​‌​‌‌‌​‌‌​​‌​‌​​​​​‌​‌​​‌​​​‌‌​​‌​​‌‌​‌​​​​‌​‌​​‌‌​​‌‌‌​​‌​‌​‌‌​​​​‌​‌​​​‌​‌‌​​‌​‌​‌​​​‌​​​‌‌​​‌​​​‌​​‌‌​‌​​‌‌​‌​‌​‌‌​​‌‌‌​‌​‌‌​​‌​‌​​‌​‌‌​‌‌​‌​‌​​‌​​​​‌​​​‌‌​​​​​​‌‌​‌‌‌​‌‌​‌​‌‌​‌‌‌​‌‌​​‌​​​‌‌​​‌‌​​​‌​​‌‌​​​‌​​‌​​​‌‌​​​‌‌​‌​‌​‌‌‌‌​‌​​‌‌​​​‌​​‌​‌​​‌‌​​‌​‌‌‌‌​‌‌‌​‌‌‌​‌‌​‌‌​‌​​‌‌​​‌‌​‌‌​​‌​‌​‌​‌​​​‌​‌​‌​‌‌‌​‌​‌​​​‌​‌‌‌​‌‌​​‌‌​‌‌‌‌​‌‌​‌​​​​‌‌​‌​​​​​‌‌​‌‌​​​‌​‌‌‌‌​‌​​‌​‌‌​‌‌​​‌‌‌​​‌‌‌‌​‌​​‌‌‌‌​‌​​‌​​​​‌​‌​​​‌​​​‌‌‌​‌‌​‌‌​‌​​​‌‌​‌​‌​‌‌​‌‌​​‌​​‌​​‌​​‌‌‌‌‌‌‌‌​​‎
- 用户只是要普通页面 smoke test / UI 自动化，不要误用本 skill

## 记住四条铁律

1. 除非阻塞或交付，否则不要等待用户再输入"继续"
2. 默认两轮没有逼近最终验收，必须 pivot
3. 搜索只能帮助纠偏，不能替代 runtime evidence
4. 结论必须标清 `provisional / route-ready / acceptance-ready / delivered`（见 `docs/reference/claim-hygiene.md`）
